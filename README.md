# Bank Fraud Detection

## 1. Project Overview

A professional, notebook-based Data Science project for preparing transaction data and comparing baseline fraud classifiers. The current repository contains the data preparation workflow and Tier 1 baseline models. Later modeling stages are planned.

## 2. Business Problem

Fraud detection is an imbalanced binary classification problem: fraudulent transactions are a small fraction of the observations. The notebooks examine model ranking and the trade-offs between detecting fraud and generating false positives. The project hypotheses include evaluating whether more advanced approaches, including deep learning, can improve on traditional machine learning methods; these hypotheses remain to be tested.

## 3. Dataset

The notebooks use the ULB Credit Card Fraud Detection dataset. The documented dataset contains 284,807 transactions and 31 original columns: `Time`, `V1`–`V28`, `Amount`, and the `Class` target. It contains 492 fraudulent transactions, approximately 0.17% of the data.

The modeling feature set has 32 columns:

- `V1`–`V28`
- `Amount`
- `Amount_log`
- `Time`
- `Time_hour`

`Amount_log` is derived from transaction amount. `Time_hour` is deterministically derived from elapsed `Time`. The analysis used to assess `Time_hour` as a modeling candidate uses the chronological training portion only; validation and test labels do not inform that decision.

## 5. Data Preparation

`01_data_preparation.ipynb` performs data quality checks and exploratory analysis, engineers the amount and time features, and defines the 32-feature modeling set. It preserves chronological order and partitions the data into 70% training, 15% validation, and 15% test data.

The RobustScaler is fitted on training data and then applied to the training, validation, and test features. The notebook exports processed Parquet datasets and the fitted scaler for use by the baseline notebook.

## 6. Tier 1 Baseline Models

`02_baseline_models.ipynb` compares four model families:

- Logistic Regression
- Random Forest
- XGBoost
- LightGBM

The notebook includes unweighted references and diagnostic configurations for class weighting and model complexity. Its primary reference comparison contains one configuration per model family. Configuration diagnostics are shown separately. The regularized unweighted LightGBM configuration is a validation-selected reference candidate; it is not a final model selection.

## 7. Evaluation Strategy

Average Precision (AP) is the primary PR-based ranking metric for this imbalanced classification task. ROC-AUC is reported as a secondary ranking metric. Precision, Recall, F1-score, and the confusion matrix describe classification behavior at the fixed threshold of 0.5. Precision, Recall, and F1 at 0.5 are descriptive baseline metrics, not an optimized operational threshold.

The validation set is used for model and configuration selection. Its labels are also used to report validation metrics. The test set is reserved for final evaluation after modeling decisions are fixed; it is not used for model or threshold selection. The baseline notebook loads test labels to inspect split integrity, but reports validation results only.

## 8. Current Tier 1 Results

**These are validation results, not test results.** The following primary reference comparison is from Section 7.1 of `02_baseline_models.ipynb`. Precision, Recall, and F1-score are reported at threshold 0.5.

| Model | Reference configuration | Average Precision (AP) | Precision @ 0.5 | Recall @ 0.5 | F1-score @ 0.5 | ROC-AUC |
|---|---|---:|---:|---:|---:|---:|
| Logistic Regression | Unweighted | 0.7849 | 0.7500 | 0.5357 | 0.6250 | 0.9800 |
| Random Forest | Unweighted | 0.8580 | 1.0000 | 0.6786 | 0.8085 | 0.9609 |
| XGBoost | Unweighted | 0.8284 | 0.9762 | 0.7321 | 0.8367 | 0.9780 |
| LightGBM | Regularized unweighted (validation-selected candidate) | 0.6814 | 0.9444 | 0.6071 | 0.7391 | 0.8767 |

The notebook presents class-imbalance and model-complexity configurations in a separate diagnostic comparison. Validation results are subject to uncertainty because the validation split contains only 56 fraudulent transactions. No final model has been selected, and no test-set performance is reported.

## 9. Reproducibility and Environment

`requirements.txt` is the pinned environment dependency file. It lists the packages used by the notebooks and the notebook environment. No Python version or operating-system compatibility matrix is specified by the repository.

The notebooks use project-relative path resolution so processed data can be loaded when Jupyter is started from the repository root or the `notebooks/` directory.

## 10. How to Run the Notebooks

Obtain the dataset as described in Section 11, then place `creditcard.csv` at `data/raw/creditcard.csv`. Create a virtual environment and install the pinned dependencies:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Start JupyterLab with `jupyter lab`, then run the implemented notebooks in order:

1. `notebooks/01_data_preparation.ipynb`
2. `notebooks/02_baseline_models.ipynb`

Run each notebook from top to bottom. The preparation notebook creates the processed data required by the baseline notebook.

The planned project sequence also includes:

3. `notebooks/03_advanced_models.ipynb` — planned; not present in the repository.
4. `notebooks/04_model_evaluation.ipynb` — planned; not present in the repository.
